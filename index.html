    2021

    prologue · 2021

    It started with a master's and a ride-sharing app.

    At DA-IICT I learned Java the way you learn a city from a map. The first time it felt real was a team project: a Spring Boot API and a React frontend that matched drivers and passengers along shared routes.

    I liked the backend half more. That was the first clue.

    2023

    chapter 1 · 2023

    First production system: attendance for 700 companies.

    I joined PeopleHum as a Software Engineer and landed on Attendance & Leave. Every punch, every leave request, every payroll cut-off for 500K+ people ran through the code I was now responsible for.

    Production has a way of teaching you what a textbook can't: a wrong number here is someone's salary.

    50M

    chapter 2 · the migration

    Fifty million records, and no maintenance window.

    Attendance & Leave had to leave the monolith. Customers run payroll on fixed calendars, so "we'll be down for the weekend" was never on the table.

    We moved 50M+ records with 100% consistency and zero downtime. I learned that the migration is the easy part; proving nothing was lost is the job.

    <1s

    chapter 3 · events

    Stop computing on a timer. Compute when something happens.

    Attendance ran as hourly batch jobs, so every punch waited for the next run. I redesigned it as an event-driven pipeline on Kafka: an employee's day is recomputed as events arrive.

    5–6 million records a day, sub-second freshness. This is still the design I'm proudest of.

    30K

    chapter 4 · the platform

    The unglamorous systems everyone depends on.

    A notification platform on Kafka with a priority-aware orchestrator. An email system doing 30K an hour at 99.99% uptime. A database integration framework pulling 5M+ records a day from client MySQL and MSSQL without a single duplicate. An overtime engine that bends to each client's rules.

    None of it is a headline. All of it is what makes the headline features work.

    102

    chapter 5 · 2026

    Senior. A hundred and two services, twenty-seven countries, five interns.

    The promotion recognised scope I already had. What changed was the blast radius: I led the Java 17 → 25 upgrade and Docker rollout across 102 services, started a payroll platform for 27 countries, and became the reporting manager for five interns.

    Leading an upgrade across a fleet is less about Java and more about getting a hundred service owners to move together.

    MCP

    chapter 6 · now

    Letting AI agents into production, carefully.

    The questions I get asked most are reporting and diagnostics questions, and they all need an engineer with database access. I'm building MCP servers that expose read-only, scoped tools over production data so an agent can answer them safely.

    Distributed systems taught me to distrust anything I can't verify. That turns out to be the right instinct for AI tooling too.

    epilogue

    What's next.

    A senior backend role where distributed systems and AI tooling both matter, on a team that cares about getting the numbers right.
